# Private object lifecycle foundation (synthetic only)

This implements the local portion of E02-T04 and advances E02-T06/T08 without attaching S3, a bucket, an upload route, user content or a product download URL. Migration `20260927_0006` adds owner-scoped `private_objects` and `private_object_versions`. It also permits reference-only `PRIVATE_OBJECT_DELETE` outbox events. The object ID is an opaque internal key. Provider version IDs are restricted metadata, never written to the outbox or logs.

An upload original starts its 30-day clock at **extraction completion**; an optional raw recording starts at **recording completion** and cannot be registered without explicit opt-in. There is no selected Evidence table yet, so a retained original must not be registered through this temporary-original path. No general chat or default-on recording route exists. Internal lookup denies wrong accounts, inactive profiles/accounts, expired objects and `DELETING` objects.

The bounded expiry pass marks due objects `DELETING` and each known version `DELETE_PENDING`, adding one outbox reference per version in the same transaction. A synthetic in-memory adapter tests all-version deletion, duplicate delivery and crash-after-delete replay. It compares provider-listed versions with the registry; an unknown provider version blocks completion. A real S3 adapter is deliberately absent: the fake handler must never be wired to a network client inside a DB transaction. A real adapter needs a separately reviewed at-least-once protocol, complete version enumeration, idempotent version-specific deletion, post-delete verification and restricted credentials. An S3 delete marker alone is not success.

Account/profile deletion previews now include private object and version IDs in their digest. Confirmation immediately blocks their reads and records `VERIFY` work items; known local object-version events can be queued, but neither the request nor object is marked `ERASED`. An old backup containing an affected private object keeps the restore gate closed until an actual provider/version reconciliation path exists. Temporary drafts/review snapshots are separately inventoried, but canonical Evidence, Graph, archive, package and external processor targets remain outside the current impact inventory, so the preview stays `FOUNDATION_ONLY` and `ready_to_execute=false`.

Synthetic tests cover separate clocks, default-off recording, owner checks, deduplication, bounded expiry, unknown versions, all-version deletion, rollback, retry after a fake adapter interruption, stale deletion digest and restore quarantine. PostgreSQL migration/check for `20260927_0006` passed on an isolated loopback `_test` DB; provider-specific row-lock behavior and an actual S3 version-store adapter remain untested.
