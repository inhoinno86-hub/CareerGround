# Canonical Graph foundation (synthetic only)

Migration `20260927_0008` adds owner-scoped `profile_change_sets`, `claims`, `evidence_sources`, `evidence_items`, `evidence_claim_links`, `claim_assessments`, `claim_reviews`, and `claim_constraints`. Composite foreign keys bind each Claim/Evidence relationship to the same account and profile. A review batch can create at most one profile change set, and a canonical mutation advances the locked profile version once. Migration `20260927_0009` adds exact version-keyed `profile_archives`.

`submit_synthetic_review` is an **internal** caller-owned transaction path. It accepts a `VerifiedReviewApproval` object intended to be produced by a future trusted user-confirmation adapter; no product route or issuer creates one. It requires an explicit decision for every item in a one-to-five item review, an exact matching review digest, active owner/profile/workspace, unchanged source hash and wording, a current profile version, and a short approval lifetime. The account/profile/workspace/batch rows are locked before mutation. A successful replay with the same decisions returns the existing change set without creating another Claim or version. A stale or changed decision is rejected.

`ACCEPT` copies only the displayed exact source substring into a durable Claim and EvidenceItem, retains the source input reference/hash and review digest, links the Evidence as `SUPPORTS`, and records `USER_CONFIRMED`. Its assessment stays `NOT_EVALUATED` and `REVIEW_REQUIRED`, so it is not eligible for publication merely because the user confirmed the wording. `EDIT` and `FOLLOW_UP` remain temporary and do not advance the canonical version. `EXCLUDE_NOT_TRUE` and `EXCLUDE_DO_NOT_USE` create durable exact-text boundaries, with the review item and digest recorded. No model or automatic extraction can silently promote a draft.

Selected Claim/Evidence survives temporary workspace expiry. Deletion preview includes every Graph row ID in the impact digest; confirmed deletion immediately blocks the account/profile and stages one local Graph purge per affected profile. The purge removes dependent rows in foreign-key order, marks local Graph impact work done only when no affected Graph rows remain, and leaves external/backup verification pending. Restore quarantine rejects an old snapshot containing affected Graph data until a complete erasure reconciliation exists. It never serves an old Graph because the temporary review rows were purged.

Before a canonical change, the locked profile's existing Graph is captured by exact version. After the change, the resulting version is captured in the same transaction. Each snapshot contains the owner/profile/version, all current canonical Graph rows, and a SHA-256 integrity hash; a repeat snapshot at one version must match byte for byte. Owner-scoped `read_profile_archive` returns only that stored version and rejects missing, erased, cross-account, or tampered versions rather than substituting the latest Graph. The service has no archive update path. Database privilege separation, immutable storage enforcement, context/ownership and artifact-trace sections remain future work.

Internal `get_career_profile` and `get_claim_evidence` projections now resolve only one stored snapshot version. A selected Evidence excerpt remains readable after its temporary profiling input expires, and the projection labels its original source as `SELECTED_EXCERPT_ONLY`. Missing old versions, erased profiles and wrong accounts fail closed. These are internal domain reads, not a public export or MCP route. Migration `0010` additionally enforces one Claim assessment per Claim/profile version; its PostgreSQL verification passed with the JD/artifact foundation. Migration `0011` adds separate [boundary and conflict review journals](CareerGround_Boundary_Conflict_Review_Foundation_2026-09-27.md), verified on local PostgreSQL 17.11.

An internal [canonical-only JSON export projection](CareerGround_Profile_Export_Foundation_2026-09-27.md) now includes active standalone boundaries and exact selected Evidence excerpts. It has no download resource or public adapter.

The isolated local product MCP factory now exposes read-only `get_career_profile`, `get_claim_evidence`, and `get_claim_review` under `career.profile.read` for synthetic accounts. Graph reads require an exact stored profile version and return the same `found=false` shape for missing and other-account IDs. Evidence output contains selected excerpts and their source availability, never a full temporary input body. The review read requires a configured HMAC secret, checks its stored digest and expiry, and reports whether its base profile version still matches; reading does not renew either value. The internal read also rejects a review when its temporary workspace is deleting, expired, or erased. This factory still has no product ASGI entrypoint or trusted approval issuer, and its read results are not a complete Phase A MCP contract.

Synthetic tests cover exact source lineage, publication-blocking assessment, mixed decisions, missing decisions, cross-account denial, source/profile staleness, replay, edit-only version stability, workspace expiry, exact archived versions across two changes, tampering, deletion preview/purge, and restored Graph quarantine. A loopback PostgreSQL 17.11 `careerground_test` database passed migrations through `0009`, `alembic check`, and the complete **140-test suite with no skips**, including exact archive retrieval in the PostgreSQL smoke test. `0006`–`0008` passed an empty-database downgrade to `0005` and re-upgrade; `0009` passed downgrade to `0008` and re-upgrade. All 24 product tables were empty after tests. Later local work added bounded conflict/boundary review and exact R1 resume review, without public adapters. The `FOUNDATION_ONLY` / `ready_to_execute=false` deletion boundary remains: provider/backup erasure, a real step-up and review approval issuer, complete archive scope, R2/R3 resume wording and public data export remain unfinished.
