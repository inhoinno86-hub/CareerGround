# Separate Claim use review foundation — synthetic only

The owner-approved Phase A policy is implemented as an isolated local synthetic browser path. Fact confirmation still creates `USER_CONFIRMED`/`NOT_EVALUATED`/`REVIEW_REQUIRED`; it never silently permits publication. The new Claim use page shows the exact archived Claim wording, selected Evidence excerpts and original source references, current assessment, and active same-scope constraints. It labels user confirmation as distinct from external verification. Two independent unchecked choices require the owner to attest that they know no conflicting account of the shown experience and to authorize this exact Claim for R1 resume use.

A three-minute signed form binds account, opaque browser session, Claim/profile IDs, current profile version, review ID, exact display digest and expiry. The domain service re-reads the archived view, locks the active account/profile, and compares the current live canonical state with the stored archive before writing. It rejects absent fact review, no supporting Evidence, any `CONTRADICTS` link, an active same-scope boundary, disputed/contradicted assessment, `DO_NOT_CLAIM`, stale version, changed wording/source, foreign session and incomplete forms. A successful transaction appends one dedicated `claim_use_reviews` journal, a `CONSISTENT`/`ALLOWED` assessment and a `CLAIM_USE_REVIEW` change set, increments the profile version once, and stores a new exact archive. Same-token retry returns the same review/version; other claims and old archives remain unchanged.

Migration `20260929_0015` adds the owner/Claim-bound review journal with explicit-choice and version-step checks. New canonical archives use `canonical-foundation-v3` to include that journal; earlier v1/v2 snapshots retain their exact contents and remain readable. Deletion preview, local purge and restore quarantine inventory the new journal. The browser factory remains unmounted in the public product and has no real user data, operational identity, AI model or external service connection.

Synthetic tests cover owner/browser isolation, missing choices, expiry/replay, version drift, prior fact review, supporting/opposing Evidence, boundaries, disputed/prohibited assessments, v2-to-v3 archive compatibility, deletion and the downstream explicit JD link → R1 wording review → Markdown export.
