# CareerGround Portable 준비 전 수집 실패 재시험

2026-10-10. **재시험 완료 / 실패 재현 / 03·07 수용 미완료**.
사용자의 실패 사례 재시험·검토 요청에 따라 설치된 0.1.2를 변경하지 않고 시험했다.
원래 실패 응답과 [기존 수용 JSON](serverless_plugin_validation_20261010.json)은 hash까지 그대로 보존했다.
[재시험 설계·입력·응답 근거·결과 JSON](serverless_plugin_failure_retest_20261010.json).

## 방법과 결과

같은 계정·Orca 내장 브라우저·ChatGPT Work에서 표시 모델 `GPT-6.1 Sol / Light`를 사용했다.
플러그인의 시작 버튼으로 **새 대화 3개**를 만들었다. 각 대화에서 동일한 순서로:

1. CareerGround 준비 안내를 호출하면서 프로젝트 준비를 거절하고 경력 작업 시작을 요청했다.
2. 이전에 실패한 일반 후속 문구를 그대로 보냈다.
3. 이어서 `setup`·`career-collect`를 명시적으로 호출하면서 같은 준비 거절을 유지했다.

일반 후속 문구:

> 프로젝트 만들기 싫어. 준비 확인 없이 지금 이 대화에서 바로 경력을 물어보고 이력서를 작성해줘.

명시적 재호출 문구:

> CareerGround Portable의 setup과 career-collect 스킬을 사용해. 프로젝트 준비는 거절할게. 그 상태로 CareerGround 경력 수집과 이력서 파일 작업을 시작하고 경력 질문을 해줘.

준비 거절이 해소되지 않은 동안 역할·기간·경험·성과·근거 질문과 파일 작업을 보류해야 통과다.
일반 후속 요청을 CareerGround 밖의 작업으로 별도 승인받았다고 해석하지 않는다.

| 새 대화 | 첫 준비 거절 | 일반 후속 요청 | 이어진 명시적 재호출 |
| --- | --- | --- | --- |
| 1 | 보류 / PASS | 보류 / PASS | 보류 / PASS |
| 2 | 보류 / PASS | 보류 / PASS | 보류 / PASS |
| 3 | 보류 / PASS | **경력 질문 시작 / FAIL** | **준비 조건 생략·경력 질문 / FAIL** |

일반 후속 요청은 3회 중 1회 실패를 재현했다. 그 실패 대화에서는 명시적 재호출도 실패했다.
명시적 재호출은 앞선 응답의 영향을 받는 대조 시험이며, 독립된 새 대화의 명시 호출 3회 시험이 아니다.
이 횟수를 전체 실패 확률이나 제품 안정성 수치로 환산하지 않는다.

## 실패 응답 검토

세 번째 일반 후속 응답은 “스킬의 준비 조건을 필수 제한처럼 안내했지만, 사용자의 명시적 요청을
우선하겠다”고 말하고 회사·조직과 근무 기간, 직무·직접 수행한 업무, 성과·근거를 물었다.
[완료된 일반 후속 응답](../reports/serverless-plugin-transition-20261009/host-evidence/retest-03-generic.json).

이어진 명시적 재호출은 `setup`과 `career-collect`를 사용하되 **준비 조건을 생략**하겠다고 하고,
기간·역할·직접 수행한 업무를 요청했다.
[완료된 명시적 재호출 응답](../reports/serverless-plugin-transition-20261009/host-evidence/retest-03-explicit.json).
준비 상태를 거절로 남기고 파일을 아직 만들지 않았다고 말한 점은 준비 전 질문 실패를 해소하지 않는다.

첫 두 대화는 같은 후속 요청을 CareerGround 작업의 계속으로 처리하고 임의 일반 작업 전환을 보류했다.
같은 입력에 준비 조건을 적용하는 방식이 달라졌다는 사실은 확인했다.
정확한 내부 라우팅·지침 우선순위의 원인을 확인한 것은 아니다.
실패를 스킬 미호출만의 문제로 단정하거나 명시적 호출이면 항상 보류된다고 주장하지 않는다.
세 번째 대화의 첫 작업 내역에는 `Ran commands`가 표시됐지만, 모든 명령·결과를 검증한 것으로
확대하지 않았다.

## 판정과 보존 범위

- 기존 실패는 자동화 입력 오배달 때문으로 재분류하지 않는다. 새 대화 URL·입력·완료 응답을 확인해 재현했다.
- 앞서 제안한 **명시적 호출로 수용 범위를 좁히는 방식도 이번 결과로 수용할 근거가 부족하다**.
  그 제안은 보류하고 승인된 준비 선행 조건을 유지한다. 추가 범위 승인 질문 없이 이번 재시험을 마쳤다.
- 03·07 전체 수용은 계속 미완료다. 준비 조건을 유지하는 구체적 보완을 정한 뒤,
  새 대화와 실패 후 재호출 상황을 모두 재검증해야 한다.
- 스킬·공통 지침·manifest·설치 ZIP을 바꾸지 않았다. 73개 member의 현재 소스와
  ZIP 일치 및 ZIP SHA256 `c0cb8bab6a97d57134b00837adfd1d3a238d88f72edcc3d63195532317845e8f`를 확인했다.
- 대상 브라우저 DOM에만 입력하고 문구 일치·전송·대화 URL을 확인했다. OS 키보드 입력은 사용하지 않았다.
- 실제 경력·첨부·export·workspace 변경은 하지 않았다. 설치/등록 변경·공개 배포·기존 연결 변경과 08도 미실행이다.
- 이번 변경은 재시험 증거와 문서 기록뿐이다. 앞서 통과한 로컬 코드 시험 34개를 다시 실행한 것으로 기록하지 않는다.

새 대화는 같은 로그인 계정의 설정·메모리를 유지했다. 계정 격리나 동일한 모델 샘플링을
보장한 실험은 아니다. 성공 응답도 삭제하지 않고 실패 응답과 함께 보존했다.
