# Temporary Claim review workspace (synthetic only)

Migration `20260927_0007` adds temporary `profiling_drafts`, `profiling_review_batches` and `profiling_review_items` with composite owner/session/scope foreign keys. A batch has at most five positions and nullable, explicit item decisions; no database default can mean approval. All rows remain tied to a profiling session and expire with that workspace. This is E02-T01/T02 storage progress and E03-T03 preparation only, not canonical Claim promotion.

`propose_verbatim_draft` accepts only a substring of one explicitly submitted input in the same account and session. It does not generate or infer a new fact. `ClaimReviewPreparation.prepare` locks the owned session/profile and drafts, requires one experience scope and the current profile version, checks the source hash, then snapshots exact wording, source input ID, type and scope. The HMAC digest binds those values plus account, session, profile, version, review purpose and expiry. `get` returns the original snapshot only and rejects tampering, expiry or wrong-account access. It does not change the canonical profile. There is no public review route or trusted approval adapter yet.

The retention worker removes these temporary rows with the expired session/input. Deletion preview includes their IDs; confirmation blocks the account/profile and queues their local cleanup. Quarantined restore replay purges them before an old synthetic copy is considered ready. Selected canonical Evidence is not stored in these tables and must get a separate retention and erasure path when the Graph schema exists.

Synthetic tests cover one-to-five item limits, mixed-scope rejection, no inferred Claim from unsupported text, stale source/profile version, digest tampering, cross-account foreign keys, deletion impact and expiry/restore cleanup. PostgreSQL migration/check for `0007` passed on an isolated local `_test` database. The internal synthetic submission and Graph storage now exist in [the canonical Graph foundation](CareerGround_Canonical_Graph_Foundation_2026-09-27.md); a real approval issuer and public route do not. `ready_to_execute=false` remains the deletion boundary.
