# Boundary and conflict review foundation (synthetic only)

Migration `20260927_0011` adds owner-scoped `claim_boundary_reviews` and `claim_conflict_reviews`, an active/revoked state for `claim_constraints`, and composite ownership keys for the reviewed constraint and opposing Evidence link. The new journals are included in deletion impact inventory, local purge, restore quarantine, and new exact-version Graph archives. Existing `canonical-foundation-v1` archive bytes remain unchanged and are validated in their original shape; a later profile version uses `canonical-foundation-v2`.

`BoundaryReviewService` prepares a ten-minute HMAC digest over the exact displayed Claim, current assessment, linked Evidence, old/proposed boundary, allowed wording, remaining prohibited expansion, owner, version, action and expiry. The internal submit path requires a matching `VerifiedBoundaryApproval` intended for a future trusted user-confirmation adapter. `ADD` needs an existing `CONTRADICTS` Evidence link and creates a `DO_NOT_USE` boundary. `REVOKE` needs a newer `SUPPORTS` Evidence item linked to the Claim; it marks the old boundary revoked and retains its historical row. Either action increments the locked profile version once, archives the new state and places affected Claims in `REVIEW_REQUIRED`. It never promotes a Claim to `ALLOWED` or changes a `NOT_TRUE` boundary.

`ConflictReviewService` binds a specific `CONTRADICTS` Evidence link, exact Claim/Evidence text, assessment, resolution, explanation, owner, version and expiry to a separate digest and approval. It retains the opposing Evidence and appends a new assessment only for that Claim. `ACCEPT_CORRECTION` blocks the old Claim with `CONTRADICTED`/`DO_NOT_CLAIM`; the other three choices remain `DISPUTED`/`REVIEW_REQUIRED`. `KEEP_EXISTING` and `KEEP_BOTH_SCOPED` are recorded as explicit review outcomes but cannot publish or create corrected/scoped Claims yet. Corrected wording and a decision to make a Claim publishable need a later exact review path.

Both services are internal synthetic paths. No approval issuer, public MCP/web command, real user data, provider, or operational scheduler is attached. The required-PostgreSQL suite passed all 156 tests without skips; all 32 product tables were empty after the test transaction rolled back.
