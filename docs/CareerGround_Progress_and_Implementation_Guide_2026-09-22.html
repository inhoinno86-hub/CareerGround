CareerGround · 2026-09-23 갱신 · 초보 개발자용 현황 설명

CareerGround는 설계의 뼈대를 만들었고,
제품을 만들 준비 단계에 있습니다.

현재까지는 “사용자의 경력을 사실에 근거해 다룰 수 있는가”를 검증했습니다. 아직 사용자가 로그인해서 대화하고, 이력서를 만들고, 음성 면접을 하는 앱은 없습니다. 다음 목표는 이 검증된 설계를 실제 서비스 기능으로 바꾸는 것입니다.

Problem

만들고 싶은 제품
CareerGround는 사용자의 경력을 대화로 정리하고, 그 근거를 보존한 채 JD 분석·이력서·면접 준비·음성 모의 면접까지 이어 주는 서비스입니다.

일반 생성형 AI는 문장을 매끄럽게 만들 수 있지만, 사용자가 실제로 하지 않은 일을 더 크게 말하게 만들 수 있습니다. 예를 들어 “기능 개발에 참여했다”는 말이 “프로젝트 전체를 책임졌다”로 바뀌면 이력서와 면접에서 문제가 됩니다.

그래서 CareerGround의 핵심 문제는 문장 생성 자체가 아니라 다음 질문에 답하는 것입니다.

  • 이 문장은 어떤 사용자 발언이나 문서에서 왔는가?
  • 사용자가 직접 수행한 일, 팀의 책임, 최종 결정권을 구분했는가?
  • 확인되지 않았거나 모순된 내용은 이력서에 쓰이지 않도록 막는가?
  • 음성 면접에서 새로 나온 이야기는 바로 사실 데이터로 저장하지 않고, 사용자가 검토하도록 하는가?

이 문제를 먼저 해결하지 않으면 GPT 플러그인이나 앱을 빨리 만들어도 신뢰하기 어려운 결과가 나올 수 있습니다.

Solution

원래 계획은 공통 기반인 Career Core를 먼저 만들고, 그 위에 GPT 플러그인과 음성 면접 앱을 연결하는 구조입니다. Career Core는 경력 사실, 근거, 이력서 문장, JD 연결 정보를 한곳에서 관리하는 백엔드와 데이터 계층입니다.

사용자 발언/이력서 │ ▼ 경력 프로파일링 ──► Claim(경력 사실 후보) ──► Evidence(근거) │ │ │ │ ▼ ▼ │ 검토·승인·금지 경계 버전 기록 │ │ ▼ ▼ Career Graph(검증된 경력 지도) │ ├──► GPT 플러그인: JD 분석 · 이력서 · 예상 질문 │ └──► Interview Package ──► 음성 면접 앱

현재 위치

원래 개발 계획의 “다음 세션 우선순위”는 7개였습니다. 이 가운데 1~6번을 완료했습니다. 따라서 설계 체크리스트 기준 6/7, 약 86%입니다. 이 비율은 코드 완성도를 뜻하지 않습니다. 실제 애플리케이션 서비스는 아직 구현 전이며, 지금까지의 성과는 제품이 지켜야 할 규칙과 전달 계약을 문서·스키마·테스트로 확정한 것입니다.

초록색: 완료 6개 · 회색: 남은 1개

원래 순서계획했던 결과물현재 상태실제로 확인된 내용
1. Career Graph Schema v1경력 데이터의 구조 정의완료개체·관계·상태·근거·이력서/JD 연결·버전 규칙을 설계했습니다.
2. Profiling ProtocolAI가 경력을 묻고 확인하는 순서완료14개 대화 상태와 확인·모순·중단 규칙을 정의했습니다.
3. Plugin Functional SpecificationGPT 플러그인 기능 계약완료도구별 입력·출력·권한·오류·확인·재시도 계약을 확정했습니다.
4. Interview Package Schema플러그인→앱 전달 데이터 계약완료JSON Schema, 고정 버전, 최소 데이터, 7일 만료, JCS·ES256 서명, 호환성·취소 규칙과 합성 검증 자료를 작성했습니다.
5. Voice Interview Agent Spec음성 면접의 대화 규칙완료상태 전이, 질문·follow-up, 전사 수정, 비점수형 평가, 후보 생성, 철회·보관 규칙과 합성 검증을 작성했습니다.
6. MVP Architecture실제 기술 구조완료모듈형 백엔드, PostgreSQL, MCP·웹 인증 경계, 저장·삭제, AWS 서울 후보, ES256 KMS, 음성 공급자 선정 게이트를 확정했습니다. 공급자 계약과 클라우드 리소스는 아직 없습니다.
7. Implementation Task Breakdown개발 가능한 작업 목록검토 대기Epic → Feature → Story → Task와 수용 기준을 담은 초안을 작성했습니다. 사용자 검토·승인 전이므로 아직 완료로 세지 않습니다.

완료된 작업이 의미하는 것

완료: 데이터 모델

무엇을 저장할지 정했습니다

경력 사실(Claim), 근거(Evidence), 역할과 실제 기여, 책임 범위, 금지 표현, 이력서 문장, JD 요구사항, 면접 중 새로 발견된 후보 정보를 분리해 저장하는 구조를 만들었습니다.

완료: 과장 방지 규칙

“참여”를 “전체 책임”으로 바꾸지 않습니다

소유 범위와 결정권을 별도로 기록합니다. 확인되지 않은 사실, 모순된 사실, 사용 금지 사실은 게시하거나 이력서에 쓰지 못하게 하는 규칙을 정의했습니다.

완료: 대화 설계

AI가 무엇을 더 물어야 하는지 정했습니다

모호한 대답을 받으면 구현·검증·결정권을 나누어 묻고, 중요한 문장은 사용자 확인을 받아야 다음 단계로 넘어가도록 정했습니다.

완료: 작은 검증 모델

규칙이 깨지는 사례를 검사합니다

가상의 경력 3개를 만들고, 근거 추적·이력서 역추적·JD 연결·금지 표현·모순 보존·버전 복원 등을 자동 검사했습니다.

첫 제품 범위: 작게 완성할 기능

처음부터 음성, PDF, 자동 지원까지 만들 필요는 없습니다. 아래의 텍스트 중심 흐름을 먼저 실제로 작동시키는 것이 가장 안전하고 검증하기 쉽습니다.

1. 사용자가 경력 한 건을 입력한다 2. 플러그인이 범위·결정권·근거를 추가 질문한다 3. 사용자가 정확한 Claim 문구를 확인한다 4. 서버가 Profile version 1에 Claim/Evidence를 저장한다 5. 사용자가 JD를 붙여 넣는다 6. 플러그인이 근거가 있는 Claim만 사용해 Resume 초안을 만든다 7. 각 Resume 문장에서 Claim과 Evidence를 다시 열어 볼 수 있다 8. 다음 단계에서 Interview Package를 발급한다

1~7단계가 완성되면 텍스트 MVP의 핵심 가설을 실제 사용자와 검증할 수 있습니다. 8단계의 서명 패키지 handoff와 그 뒤 음성 앱은 같은 데이터를 재사용하므로, 별도의 경력 데이터 구조를 다시 만들 필요가 없습니다.
