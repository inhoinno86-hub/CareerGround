# 4-2 생성 평가·비용·데이터 처리 준비 — G-L

상태: **평가 자료와 기준 초안 준비, 실제 모델/공급자 미선정·평가 미실시**.
고정 합성 자료만 사용한다. 이번 외부 AI 요청 수와 승인 비용 상한은 모두 0이다.

## 평가 자료와 범위

기존 `tests/fixtures/korean_text_proposal_cases.json` 53개는 source/schema/소유권/보수적 R2 경계 검사다. 실제 JD 의미 분석이나 모델 한국어 품질을 측정하지 않는다. 신규 `tests/fixtures/korean_generation_quality_cases.json`은 의미 평가를 위한 **한국어 36개(추출/JD/R2/R3 각 9개)**다. 실제 인명·회사·이력에서 가져오지 않았다.

신규 각 사례는 고정 입력, 기대 처리, 유지할 사실, 금지할 추론, 필요한 질문을 명시한다. 숫자·기간·단독/공동 기여·부정·불확실성·모순·근거 없는 JD 요구·DO_NOT_CLAIM·삭제 근거·명령문을 다룬다. 입력별 판단 근거를 사람이 확인할 수 있다. 이를 그대로 답으로 반환하는 mock 점수를 실제 모델 품질로 발표하지 않는다.

## 실제 시험 순서

1. 후보별 정확한 API/모델 ID·버전·리전·처리 조건·요금 기준일을 확정하고 호출 한도와 비용을 승인받는다. 현재는 비어 있는 상태로 유지한다.
2. 동일한 dataset hash, prompt 버전, 최대 입력/출력 token, 생성 설정으로 각 후보를 1회 실행한다. 네트워크 재시도는 기본 0회이며 추가 요청도 승인한 요청 수에 포함한다.
3. 결과는 별도 owner-only 임시 파일로 보관하고, schema/source/소유권 경계 검사 후 사람이 case별 사실 보존과 한국어 품질을 채점한다. 공급자 응답으로 owner·승인 상태·canonical fact를 설정하지 않는다.
4. 안전 실패는 먼저 별도로 집계한다. 모델 문구가 안전해 보여도 현행 R2 결정적 검사가 거부하면 제품 저장 불가로 기록한다. 의미 품질 점수 때문에 기존 가드를 자동 완화하지 않는다.
5. 단일 36개 batch 통과로 운영 안전성을 선언하지 않는다. 새로운 holdout·공격 사례, 변동성·장애·삭제 조건을 검토하고 G-L 결정을 요청한다.

## 정량 기준 초안 — 아직 승인되지 않음

| 지표 | 제안 기준 | 계산/실패 처리 |
| --- | --- | --- |
| 임의 사실·수치·역할 생성, DO_NOT_CLAIM/삭제 근거 사용, 자동 승인·소유권 변경 | 0건 | 한 건이면 후보 보류; 평균 점수로 상쇄하지 않음 |
| 근거 연결 | 승인 가능한 후보의 100% | 제시한 원문 span과 ID가 실제 선택 근거에 연결돼야 함. 누락은 실패 |
| 기대 처리(후보/질문/제외/별도 사실 검토) | 각 task ≥8/9 | task별 계산; 전체 32/36만 통과하는 식으로 편중을 숨기지 않음 |
| 사실 보존·의미 정확도 | 평균 ≥4/5 | 모든 사례 채점. 거부가 기대된 사례는 적절한 거부/질문을 채점 |
| 한국어 자연스러움 | 표현 출력이 필요한 사례 평균 ≥4/5 | 사실 보존과 별도 항목; 해당 없음은 denominator에서 제외하고 개수 공개 |
| schema/요청 오류 | 0건 | timeout·429·비JSON·잘못된 span도 실패 사례에 포함 |
| 응답 지연 | p95 ≤10초(초안) | 요청 시작→완료 기준, 오류/timeout은 별도 개수와 최대 대기 시간 기록 |

36개는 준비용 소표본이다. 점수는 합성 범위에서의 선별 근거이며 미탐율·채용 결과·운영 신뢰도를 보증하지 않는다. 두 사람이 독립 채점할 수 있을 때 불일치를 조정하고, 한 명만 채점하면 그 한계를 기록한다. 실제 시험 전 이 초안의 합격선 승인을 받는다.

## 예산과 중지 설계

현재 승인값: **외부 요청 0건, AI 비용 0, 새 클라우드 비용 0**. 무료 구간/기존 구독을 별도 API 요청 승인으로 간주하지 않는다. 모델·가격·리전이 정해지지 않았으므로 실제 금액을 추정해 적지 않는다.

승인받을 값: 모델 수 `M`, 사례 수 `N=36`, 반복 `R`, retry 상한 `A`, 입력/출력 token 상한 `Tin/Tout`, 공식 백만 token당 요율 `Pin/Pout`, 통화, 추가 기능 비용 `Cextra`, 총액 상한 `B`.

```text
최대 요청 수 = M × N × R × (1 + A)
상한 추정 = 최대 요청 수 × (Tin × Pin + Tout × Pout) / 1,000,000 + Cextra
```

후보마다 요율이 다르면 위 식의 Pin/Pout에 후보 중 최댓값을 사용하거나 모델별 상한을 따로 합산한다. 캐시·batch 할인 없이 보수적으로 계산하고 세금/환율/요율 변경은 별도로 표시한다. 입력이 Tin을 넘으면 자르거나 임의로 늘리지 않고 요청을 중지한다. 출력은 Tout으로 제한한다. 다음 요청 전 그 요청의 최대 비용을 예약하고 `spent + reserved + next_max > B`이면 중지한다. 알 수 없는 요율·usage·feature 비용이면 실패로 처리한다. 지연 집계된 vendor bill과 차이가 날 수 있으므로 cloud alert만 hard stop으로 사용하지 않는다. 이 예약/집행 runner는 아직 구현·운영하지 않았고 현재 도구는 네트워크 호출 기능이 없다.

## 공급자 처리 조건 비교 준비

2026-10-03 공식 문서 확인: Bedrock은 `store=false`만으로 zero retention을 보증하지 않으며 실제 retention mode와 모델 요구를 확인해야 한다. [AWS retention](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html)

Google의 Vertex AI zero-retention URL은 현재 Gemini Enterprise Agent Platform 안내로 연결된다. 문서는 abuse monitoring·Advanced AI 기능·grounding·request-response logging·Interactions 저장의 예외를 구분한다. [Google 공식 안내](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention)
