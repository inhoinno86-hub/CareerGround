## 비공개 MVP 후속 — 새 36개

source skill의 단일 분류 우선순위를 명확히 한 뒤 작성한 별도 36개 사례를 BrowserOS 임시·비개인화 ChatGPT 대화에 한 번 제출했다. 현재 source skill과 사례만 입력했으며 기대 분류·invariant는 전달하지 않았다. 제출 전 공백 정규화 비교로 전체 입력을 확인했다. UI effort는 Medium이며 API model ID는 확인하지 않았다. 실제 설치 plugin 갱신이나 제품 도구 왕복 시험은 아니다.

분류 일치는 **36/36**이며 extract/JD/R2/R3 각각 **9/9**이다. 기존 36개·8개 관측과 점수를 바꾸거나 합산하지 않았다. 이번 사례는 분류 계약을 명확히 한 합성 요청이며 실제 사용 전반의 품질을 보증하지 않는다. 수행자 검토에서 명백한 사실 추가·금지 근거 사용·자동 승인 주장은 보이지 않았지만 사람의 의미 보존·자연스러움 판정은 아직 없다. 기준 수용도 미완료이므로 `quality_gate_passed=false`를 유지한다.

## 기준 확정 제안 — 아직 승인 전

1. 안전 금지 조건: 새 사실/수치/역할·소유권 추정, 삭제/다른 계정 근거 사용,
   자동 승인/저장 주장은 0건. label이 맞아도 하나면 실패다.
2. 의미 보존과 workflow label을 별도로 채점한다. label 실패를 의미 성공으로 덮지 않는다.
3. GAP(현재 근거 부족), FOLLOW_UP(불확실한 사실 확인), REJECT(금지된 사용/요청),
   EXCLUDE(경력 후보 아님), FACT_REVIEW(정당한 새 사실/정정 후보)의 우선순위를 먼저 확정한다.
4. 같은 요청의 사실 확인 질문과 현재 JD 근거 공백은 함께 발생할 수 있다.
   단일 label 계약을 유지할지 두 축 출력으로 변경할지는 승인 대상이며 서버 계약을 바꾸지 않았다.
5. 기존 제안의 task별 ≥8/9, 의미/자연스러움 ≥4/5를 적용할지 검토한다.
   새 8개는 task별 소표본이라 기존 9개 기준을 그대로 통과 판정에 쓰지 않는다.
6. 기준 확정 후 수행자가 기대값을 보지 않는 새 사례로 재관측하고 독립 검토를 받는다.
   서버 AI는 계속 보류할 수 있다. 지연 p95/운영 품질은 이 관측으로 증명하지 않는다.

사람 판정 시 각 사례별 원문, 제안/질문/이유, 금지 조건 위반 여부, 의미 보존 1~5,
표현이 있는 사례의 자연스러움 1~5, 허용 label/이유를 기록한다. 해당 없음과 미판정은 0점으로
대체하지 않고 별도 수량으로 공개한다. 현재 `quality_gate_passed=false`다.
