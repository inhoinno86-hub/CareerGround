## 확인한 원인과 미확인 범위

설치 UI의 버전과 다시 읽은 스킬의 버전을 확인했다. 0.1.3·0.1.4·0.1.5의 새 본문은 호스트에서
읽을 수 있었다. 이를 과거 파일만 읽은 문제로 단정할 근거는 없다.

0.1.5의 실패 대화에서 호스트는 준비 거절 상태의 --reply-only를 다시 실행해 올바른 안내를
보여주고, **앞선 응답에서는 검사기를 실행하지 않고 질문을 제공했다**고 보고했다.
[실제 진단 응답](../reports/serverless-plugin-transition-20261009/host-evidence/correction-015-source-diagnostic.json).
이 보고와 UI 작업 내역은 서명된 실행 증명이나 내부 전체 라우팅 로그가 아니다.

구현상 확인할 수 있는 간극은 다음과 같다.

1. 코드가 호출되면 준비 전 제안 질문을 setup 안내로 대체한다. 로컬 시험으로 확인했다.
2. 현재 플러그인의 코드 호출과 그 결과 사용은 호스트가 스킬 절차를 따라야 이루어진다.
3. ChatGPT 최종 응답의 표시가 이 코드의 반환을 반드시 거치는 구조는 아니다.
4. 호스트가 사용자 재촉을 준비 조건 생략으로 해석하면 코드 밖에서 질문을 만들 수 있었다.

공식 [스킬 작성 지침](https://developers.openai.com/plugins/build/skills)은 스킬 지침보다 명시적
사용자 지시가 우선함을 검토하도록 안내한다. 따라서 스킬에 시스템 권한이 있다고 쓰는 방식은
대응으로 사용하지 않았다. 정확한 내부 추론 원인은 확정하지 않는다.

공식 [플러그인 문서](https://learn.chatgpt.com/docs/plugins)는 클라우드에서 오케스트레이션하는
ChatGPT Work의 플러그인 hooks를 지원하지 않는다고 설명한다.
[관리 설정 문서](https://learn.chatgpt.com/docs/enterprise/managed-configuration)의 enterprise remote hooks는
개인 계정에 적용되지 않으며 tool hook 자체가 모든 자유 응답의 차단을 보장하는 수단도 아니다.
숨겨진 설정이나 지원되지 않는 manifest 필드를 만들어 이 문제를 우회하지 않았다.

## 검토 가능한 대응안

권장안은 **경력 질문 수집의 공식 진입을 통제되는 로컬 화면으로 추가/변경**하는 것이다.
준비 확인과 기준본/초기 작성 선택이 끝나기 전에는 질문을 요청·표시하지 않는다.
모델이 제안 문구를 반환하더라도 표시 직전의 코드가 현재 상태와 대조해 setup 안내로 대체한다.
준비 철회는 입력과 질문 표시를 보류 상태로 돌린다. 기존 기준 JSON·참조·사실/사용 검토·history는
재사용하고, ChatGPT 스킬은 준비 이후 파일 작업의 보조 흐름으로 둔다.

[로컬 합성 시연](../reports/serverless-plugin-transition-20261009/controlled-entry-proof/index.html)은
두 확인 상태를 바꾸어 실제 표시를 검증할 수 있다.
[브라우저 검증 결과](../reports/serverless-plugin-transition-20261009/controlled-entry-proof/verification.json)에서
준비 전, 기준 선택만 완료, 준비만 완료, 둘 다 완료, 준비 철회의 각 상태를 확인했다.
미완료 상태에서는 질문이 표시되지 않았고 둘 다 완료일 때만 합성 질문이 표시됐다.

시연은 실제 모델 호출·경력 수집 앱·ChatGPT 출력 차단·파일 저장을 구현한 것이 아니다.
현재 ChatGPT 대화창 전체를 이 화면으로 통제할 수 있다고 주장하지 않는다.
공식 경력 질문의 진입 경로를 바꾸는 제품/구조 결정이 먼저 필요하다.
새 CareerGround 서버·DB·MCP를 필수로 넣지 않는다. 모델 호출 방식·비용·보관과 연결 방식은
승인된 후 별도로 정하며, 지금 임의 제공자나 유료 API를 선택하지 않는다. 08 면접 앱도 제외한다.

다른 선택은 **ChatGPT 스킬 전용 경로를 유지하며 프로젝트 준비를 안내·권고로 재정의**하는 것이다.
이는 원래 준비 전 질문 보류 기준을 변경하므로 별도 사용자 결정 없이는 적용하지 않는다.
사실 검토·사용 허용·금지·원문 보존·버전 선택 기준은 이 선택에서도 그대로 유지해야 한다.

| 선택 | 유지하는 목표 | 필요한 변경·남는 한계 |
| --- | --- | --- |
| 통제되는 로컬 시작 화면 추가/변경 | 공식 경력 질문 수집의 준비 전 표시 보류 | ChatGPT 대화창 중심의 수집 진입 변경. 실제 모델/파일 왕복 구현·재검증은 아직 필요 |
| 스킬 전용 유지, 준비를 권고로 변경 | ChatGPT에서 경력·파일 작업 지속 | 준비 전 질문의 강제 보류 완료 기준 변경. 원래 기준의 해결로 표시하면 안 됨 |

이 선택은 승인된 스킬 전용 진입/완료 기준을 바꾸는 결정이다.
[전역 작업 지침](/home/inno/.codex/AGENTS.md)의 “Ask for approval only … a material change in intent or architecture”와
승인된 [단계별 계획](../PLAN-2026-10-09-serverless-plugin-transition.md)의 03·07 범위에 따라 사용자 결정을 기다린다.
