# 사실 확인과 별도 사용 검토

## 프로젝트 권고와 기준 자료 선택 — 0.2.0

프로젝트는 경력·근거 재사용, 기본/맞춤 이력서와 history 관리, 새 대화 재개,
면접 전달 버전 관리를 돕는 권장 작업 공간이다. 경력 작업의 필수 조건은 아니다.
사용자가 프로젝트를 거절하거나 밖·불명·미지원·이동 실패이면 현재 대화와 선택 파일로 계속한다.
이 상태를 준비 완료나 소속 인증으로 바꾸지 않고, 준비 확인을 반복하거나 작업을 차단하지 않는다.

현재 접근 가능한 기준 JSON의 workspace/profile ID·버전 또는 초기 작성 선택은 확인한다.
파일 없음은 초기 작성 선택, 복수 기준본·다른 프로필·충돌은 사용자 선택을 받는다.
같은 대화에서 이미 선택한 자료는 재사용하고 새 대화에서는 다시 선택한다.
파일 접근 실패를 기억으로 채우거나 선택하지 않은 자료를 병합하지 않는다.
[공통 시작 규칙](references/workflow.md)을 적용한다.

프로젝트 사용 여부는 사실 확인·사용 허용·사용 금지의 변경 승인이 아니다.
역할·기간·수치·공동 기여·원문·출처와 정확한 문구 검토 기준을 그대로 유지한다.
선택 자료의 생성·검사·다운로드·선택적 프로젝트 등록·앱 전달은 별도 상태다.

[공통 규칙](references/workflow.md)을 적용한다. 해당 버전의 실제 원문·후보·기간·역할·
공동 기여·미측정 수치·상충·사용 금지를 함께 보여 준다.
사실별로 “이 정확한 문구와 범위가 맞나요?”를 확인한다.
이어 “기본 이력서 / 맞춤 이력서 / 면접 중 어디에 사용해도 되나요?”를 따로 확인한다.
전체 승인으로 불명확한 항목을 묵시 승인하지 않는다. 무응답·거절은 pending/review_required다.

대화에서 받은 실제 선택 기록만 confirmation와 permission에 각각 남긴다.
본인 확인을 외부 검증·서버 receipt로 표시하지 않는다. externally_verified는
실제로 검토한 외부 출처 ID와 확인 범위가 있을 때만 쓴다.
허용 scope와 record를 남기고 forbidden은 scope=[]로 유지한다.
사용 금지를 풀려면 사용자에게 기존 제약과 변경 범위를 명시해 별도 검토받는다.
상충은 자동 해소하지 않고 관련 사실 사용을 보류한다.

정정·신규 사실·면접 후보는 정확한 출처와 새 사실 검토를 거친다.
기존 확인을 정정 문구에 재사용하지 않는다. 새 profile 버전과 fact_review/use_review history를
생성하며 이전 파일을 보존한다. 모델 요약만으로 사실을 확인하지 않는다.
기본 이력서 스킬(`base-resume`)에 허용된 사실과 금지·기여 경계를 전달한다.
